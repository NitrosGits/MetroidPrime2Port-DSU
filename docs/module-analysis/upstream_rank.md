# Upstream module ranking for play-check lanes

Every module with status `upstream` in `docs/modules.tsv` (66 of them: the port compiles
PrimeDecomp's source for them as-is), ranked to pick the next in-game play-check lanes.
Base `b86f94f01` (branch `decomp/rank1`), run 2026-10-23.

## Columns

- **module**, **REL id**, **text_bytes**, **functions**, **areas** — from `docs/modules.tsv`
  (generated by `tools/rel_manifest.py`; `areas` = number of areas whose spawn list names the
  module, the `spawns` column lists them).
- **hollow** — number of flagged bodies from `tools/upstream_hollow.py` (default threshold
  retail >= 0x40 bytes: EMPTY / TINY / LOWMATCH / STUB / MISSING / UNPAIRED, bodies with a
  `// @ fn_` marker not counted); **hollow bytes** is the tool's estimated missing retail bytes.
- **call / const / nan / shape** — findings of that kind from `tools/retail_diff.py` for the
  module's *marked* (ported) functions. 0 also means the module has no parsed marked body to
  check (see the notes).
- **markers** — `// @ fn_<id>_<off>` markers for the module's REL id, counted with the parser in
  `tools/port_progress.py`.

Sort: `hollow + call` findings descending, ties by `text_bytes` descending.

## Commands

    # per module, from the rank1 worktree (its build/G2ME01 is a symlink to wt-mp2-port's
    # matching build: report.json + the .o files are identical for these modules)
    python3 tools/upstream_hollow.py --top 0 <Module>
    python3 tools/retail_diff.py --module <Module>
    # markers per REL id (the parser tools/port_progress.py uses)
    python3 -c "import sys,collections; sys.path.insert(0,'tools'); import port_progress as pp; \
      print(collections.Counter(m for m, _ in pp.markers()))"

Raw tool output for all 66 modules: `/tmp/opencode/rank1/{hollow,diff}/<Module>.txt` (not committed).

## Notes

- Only two modules come back hollow at the default threshold: **MediumIng** (7 hollow bodies,
  1312 bytes, plus 10 unpaired `fn_41_*` retail functions with no upstream symbol; module lines
  44.6% in the up1 survey) and **IngSnatchingSwarm** (1 hollow body, 46 bytes, 1 unpaired `fn_*`;
  not spawned by any shipped area, module lines 0.2%). The other 64 upstream sources are at or
  near a full match, so their ranking falls through to `text_bytes`: for them a play check is
  about behaviour in game, not about missing code.
- 7 modules are spawned by no area (`areas` 0), so they cannot be play-checked as actors:
  `Tweaks`, `DestructibleBarrier`, `ChozoGhost`, `SpankWeed`, `ScriptCoin`, `Ripper`, `ScriptRsfAudio`.
  `Tweaks` (rank 4 by size) and most `Script*` ones are shared/utility or unused code.
- Only **Metroid** (call 15) and **MediumIng** (call 8, nan 3) have `retail_diff` findings, and
  only because they are the only upstream modules with markers whose port bodies `tools/asmcheck.py`
  parses (24 + 34 bodies; the port has 58 markers in upstream modules in total). `retail_diff`
  also reports 69 markers port-wide without a parsed body, so a 0 in the call/const/nan/shape
  columns is "nothing checked", not "nothing wrong".
- MediumIng's 8 `call` findings are 7 distinct unported callees (`fn_41_1930`, `fn_41_6760`,
  `fn_41_684C` x2, `fn_41_1378`, `fn_41_A0C0`, `fn_41_1ED0`, and the DOL-side `fn_25_6750`); its 3
  `nan` findings are one plain-`bge` float compare with 0 strict compares (`fn_41_155C`,
  0x1648) plus two negated `!(a <= b)` forms retail does not have (`fn_41_155C`, `fn_41_9F84`).
  Metroid's 15 `call` findings are 14 distinct callees (13 unported `fn_40_*` bodies, one named
  differently: `SetTransform__6CActorFRC12CTransform4f`); no const/nan/shape findings either way.
- No tool errors on any of the 66 modules.
